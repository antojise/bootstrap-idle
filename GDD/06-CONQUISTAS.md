# Conquistas

## Por que elas existem

No ATM, enquanto você persegue um objetivo que vai levar dias, o jogo te paga o tempo todo
em coisas pequenas: +5% de velocidade numa máquina, um slot de inventário, um multiplicador.
É isso que sustenta a atenção enquanto a vitória grande cozinha.

Três regras:

1. **Toda conquista dá alguma coisa.** Uma conquista puramente decorativa é uma notificação
   que interrompe o jogador sem pagar nada.
2. **São permanentes entre recompilações.** Junto com os fragmentos, são a única coisa que
   atravessa o reset. Isso faz o Ato V ser uma decisão e não uma perda.
3. **Nunca bloqueiam conteúdo.** Nenhuma forja, nó ou melhoria depende de conquista. Elas
   aceleram; não destrancam.

## Números

- **55 conquistas** em 8 categorias
- **6 ocultas** — a lista mostra só a contagem ("6 ocultas restantes"), nunca a dica
- **+415%** de produção somados, se todas forem obtidas
- **+1 ciclo** no total (só *Nada esquecido*, forjar os 25 comandos numa run) — o teto de
  ciclos é a tensão central do jogo e não pode ser inflado por conquista

## Como aparecem

Um toast discreto no rodapé, 2,5 segundos, sem modal e sem pausar nada. O jogo **nunca**
interrompe o jogador para comemorar. A aba CONQUISTAS mostra as obtidas com a data e as
pendentes com a condição e, quando é numérica, a barra de progresso:

```
Mil por segundo          847 B/s → 1.000 B/s   ████████░░  85%
```

Uma conquista com progresso mensurável **sempre** mostra a barra. Isso a transforma de
surpresa em objetivo, que é o que a gente quer.

## Implementação

Vive em `achievements.js`, no mesmo padrão de `data.js`: dado canônico consumido pelo jogo e
por este documento. Cada conquista é uma função pura `(S) => boolean` avaliada a cada tick,
sem efeito colateral. O estado `S` que elas recebem precisa expor, além do estado normal:

| Campo | O que é |
|---|---|
| `bytesTotal`, `execTotal` | acumulados de vida inteira, atravessam recompilação |
| `permTotal` | permissões já emitidas |
| `rate` | produção passiva atual, B/s |
| `ciclosTotais` | base + comprados + de comandos + de conquista |
| `ultimoOffline` | segundos do último retorno |
| `travadoPorPerm` | segundos acumulados com forja bloqueada só por falta de permissão |
| `ticksPerdidos`, `tempoNoFrio` | contadores da rede |
| `runs`, `arqsUsadas` | histórico de recompilações |
| `tempoAoTier8`, `recompCedo`, `forjouTier5SemDaemon`, `tempoOcioso` | flags de conquista |

Esses campos existem **só** para as conquistas. Vale a pena isolá-los num objeto
`S.stats` para que o estado principal do jogo não vire um depósito.
